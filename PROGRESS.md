**Phase 3 (lease, fencing, orphan killing) in progress:**

- 3.2 — Self-fencing: `conn.Runner` now tracks a `FenceDeadline` measured from each heartbeat's *send* time, extended only once that heartbeat's ack arrives (never on a bare send) - the mirror image of task 3.1's coordinator-side invariant, and provably never fires before the coordinator would requeue for the same reason. `internal/agent/lease.Watcher` polls that deadline and fires `OnFence` exactly once per crossing, resetting if a reconnect extends it back into the future. `exec.Executor.FenceAll` stops every running container (`SIGTERM`, 10s grace, `SIGKILL` - existing `Runtime.Stop` semantics) and marks each one so its eventual `TaskFinished` reports `"fenced"` rather than whatever exit code `SIGKILL` happens to produce; `Executor.ReplayPending` resends any `TaskFinished` that couldn't be confirmed delivered (the fenced report itself, most notably) once `conn.Runner`'s `OnRegistered` fires again after a reconnect. Wired into `cmd/agent/run.go`. `TestSelfFence` (`-tags=integration`, real podman, a hand-rolled blockable gRPC stream double standing in for an iptables DROP of the agent's inbound traffic - no firewall access in this sandbox): a real `sleep 300` container dies and gets reported `"fenced"` within lease_s(3)+10s+slack of the connection going dark, every run. Also fixed two things found while regression-testing this task, both pre-existing and unrelated to 3.2's own code: `clock.Fake` wasn't safe for the watcher-polls-while-test-advances concurrency pattern (`-race` caught it; now mutex-guarded), and this VM's podman was found upgraded to a version defaulting to the `journald` log driver, which silently broke `Runtime.Logs()` reading via the Docker-compatible API (`ContainerLogs` reads from `k8s-file`, not journald) - fixed by pinning `LogConfig` explicitly at container creation rather than inheriting the host default.
