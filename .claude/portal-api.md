# Portal REST API (`internal/coordinator/portalapi`)

Plain REST/JSON under `/api/portal/*`, backing the customer and provider web apps. Back to [README](README.md). It wraps the same `store.Store` / `api.CustomerServer` logic as gRPC rather than re-implementing it. Frontend consumer: [web-frontend](web-frontend.md).

## Auth and sessions
- Username/password accounts (portal credentials table, migration 012); sign-up for customer and provider, `POST /api/portal/login` (unified), role-specific logins. Sessions in `sessions` (013), httpOnly `SameSite=Lax` cookie, 7-day TTL, `Secure` unless dev mode. `lockout.go` locks a username after 10 failed logins in 5 min. **Per-IP limits** (`server.go` `rateLimited`, package `internal/coordinator/ratelimit`): 30 req/s (burst 120) for everything under `/api/portal/`, plus 10 logins/min and 5 sign-ups/10 min, answered `429` with `Retry-After`; the IP is the socket address, never `X-Forwarded-For`. JSON bodies are capped at 1 MiB (`413`). If the portal is ever put behind a reverse proxy, the limiter must be taught the proxy's header or every client shares one bucket. Account-scoped: every handler uses the session's `AccountID`; never trust IDs from the client without `getOwn…` checks.
- Production is **plain HTTP** today, so `Secure` cookies behave per config; HTTPS is backlog 8.18.

## Routes (see `server.go` for the authoritative list)
- Auth: `POST …/customer/signup|login` (**a new customer account starts with $100**, `signupBonusMicros` in `auth_handlers.go`; providers start at 0; the add-funds faucet is separate), `…/provider/signup|login`, `POST /login`, `POST /logout`, `GET /me`.
- Customer: `tasks` (POST submit, GET list = **only the newest 200** (`recentTasksLimit`), GET `summary` = counts over ALL the account's tasks (`summary_handlers.go`, `Store.AccountTaskSummary`: by state, running = dispatched+running, queued = queued+reserved, running cores, the outcomes of tasks finished in the last 7 days (`finishedWindow`; the Overview ring and "N of M this week", plus `finished_by_state` for the hover breakdown), unfinished tasks using any gateway, and per gateway running/queued and the newest task that used it): **any page that counts tasks must use the summary, never count the list**, `{id}` GET, `{id}/cancel`, `{id}/logs`, `{id}/usage`, `{id}/traffic`), `gateways` (GET/POST, GET `rate[?gateway=id]` = the live bandwidth (`rate_handlers.go` `computeRate`: bits per second as the average of the last three complete 10-second bins, the open bin left out, so about 10-15 s behind; a 5-minute series of 30 bins with real zeros, the busiest bin, per gateway incl. idle ones and the reported `max_mbps`; built from `task_gateway_samples` via `Store.GatewaySamples`, account-scoped; 404 for another account's gateway), DELETE `{id}` = archive: 204, 409 while a task that has not finished uses it, 404 for another account's; revokes the token and drops the live relay connection via `Server.Disconnector`; `{id}/traffic`, `{id}/test`), `ledger`, `balance/add` (dev-style top-up, there is no payment rail), `events` (SSE), `me`.
- Provider: `nodes` (GET list, `{id}`, DELETE `{id}` = remove machine + ask agent to exit, `{id}/usage`, `{id}/tasks`, `nodes/install-token` POST = mint an agent token and return the install command for the chosen offer), `ledger`, `events` (SSE), `me`.

## Files
`auth_handlers.go` login/signup/me · `customer_handlers.go` · `provider_handlers.go` (`toNodeView`, install command, offer validation; `nodeView` has `reserved_cores`/`reserved_memory_mb` from `Store.NodeReservations` = sum over reserved/dispatched/running tasks) · `traffic_handlers.go` / `usage_handlers.go` (time-series: 5-minute buckets, raw 30 s heartbeat rows for the 1-hour view, 10 s gateway samples) · `events_handler.go` + `sse.go` (one SSE stream per tab fed by `events`) · `version_info.go` (`versionView{version, latest_version, update_state}` embedded in `nodeView` and `gatewayView` (`latest_version` is the newest release that changed *that program*: `version.AgentRelease` for machines, `version.GatewayRelease` for gateways); `gatewayView` also has `max_mbps` (null until the gateway reports it)) · `json.go` helpers · `lockout.go` · `session.go`.

## Behaviors to preserve
- **Install-token validation:** cores 0.25–1024, memory ≥ 256 MB, storage ≥ 1 GB (whole GB), network 1–100,000 Mbps; the server rejects fractions/non-whole-GB sizes. The returned command uses `docker.io/fattymango/lazycake-agent:latest`, `--replace --name lazycake-agent`, `--restart=always`, `--pid=host --cap-add=SYS_ADMIN`, host networking, `LAZYCAKE_TOKEN` and the `LAZYCAKE_OFFER_*` variables.
- **Show measurements exactly** (no rounding that hides small CPU use) — the owner's transparency rule.
- Machine and gateway JSON include the version fields; gateway test (`…/test`) returns a four-state result (`green/yellow/red/grey`; grey = old gateway that cannot verify services).
- Serve the SPA with deep-link fallback (refreshing `/tasks/…` must load the app; the Go file server once broke this — covered by `web/e2e/behaviour.mjs`).
