# Tools and helper programs

Back to [README](README.md).

| Program | Purpose | Notes |
|---|---|---|
| `cmd/lcctl` | customer CLI against the gRPC `CustomerService`: `submit` (incl. `--count` for fleets), `status`, `logs`, `cancel`, `nodes`, `gateway` | files `submit.go status.go logs.go cancel.go nodes.go gateway.go client.go`; talks gRPC with a customer bearer token |
| `cmd/lcinit` | static PID-1 wrapper bind-mounted into every task container (`LAZYCAKE_LCINIT_PATH` on the agent): runs the real entrypoint as a child, enforces the wall timeout with a hard exit **from inside the container** (works even if the agent and host die), forwards signals | Linux/other signal files; built statically (`CGO_ENABLED=0`) in `deploy/Dockerfile` |
| `cmd/lcbench` | public benchmark workload: burns CPU on N workers and allocates memory stepwise, prints cgroup-observed use each second — proves a node really caps a task | env `LCBENCH_DURATION`, `LCBENCH_WORKERS`, `LCBENCH_MEM_STEP_MB`, `LCBENCH_MEM_MAX_MB`; default is also the image's entrypoint |
| `cmd/refworkload` | reference workload (Monte Carlo option pricing; CPU-bound, tiny inputs, tolerates being killed); result is one JSON line on stdout | params `LAZYCAKE_MC_*`; seed varies per task |
| `tools/loadtest/loadtest.py` | production load test through the customer portal API: mixed sizes, benchmarks, network tasks through two gateways, deliberate failures, cancellations, bursts up to 300 in flight, with safety stops (coordinator unresponsive, server disk < 700 MB, balance < $50, queue stalled 5 min) | see `tools/loadtest/README.md` and `docs/LOAD_TEST_2026-10-07.md`; needs env `LAZYCAKE_BASE/USER/PASSWORD/GW_SMALL/GW_BIG[/SSH]`; never print the password |
| `web/e2e/*.mjs` | puppeteer-core browser checks | see [testing](testing.md) |
| `docs/diagrams/make_diagrams.py` + `export.sh` | the architecture diagrams as **one Excalidraw file** (`lazycake-architecture.excalidraw`: overview, one task step by step, how a gateway works, side by side with a title and a vertical line between them). `make_diagrams.py` writes the file (`--separate` also writes one per diagram); `export.sh` renders PNG (2x) and SVG with Excalidraw's own renderer in headless Chrome (first run installs the tooling under `docs/diagrams/export/`, gitignored) | open the `.excalidraw` at excalidraw.com to edit by hand, or change the layout in the script and regenerate; keep the diagrams in step with `.claude/architecture.md` and `https.md` when the design changes |
| `web/e2e/seed_showcase.py` | **showcase demo history** for screenshots (a post, a talk): 30 days of busy, realistic data for a customer and a provider account (about 5,000 finished tasks at ~99% success, 4 machines with usage history and offline gaps, gateway traffic, ledger charges and credits). **Nothing runs**: every task is already finished, so no agent does work and the scheduler has nothing to dispatch. Every row has `01M5DEMO` in its id; `--clean` removes exactly those rows and moves the earlier real tasks back; `--hero` puts 2 queued, 3 running and 1 failed task at the top of the task list (running ones get CPU readings, logs and machine usage; the queued ones are `riscv64`, an architecture no machine offers, so nothing can ever claim them; rerun it right before photos because "running for" counts from the insert time); `--live --live-gateway id:Mbps` refreshes the last 5 minutes of gateway bandwidth, the running tasks' readings and the machines' heartbeats (they go stale in about a minute, so loop it while taking screenshots). Run once per database; for the demo accounts `--customer alice --provider bob` | needs the two portal accounts to exist. It also moves the account's earlier (real test) tasks, ledger and meter rows 45 days back so the 7-day success rate is over the demo history. It was run against **production** once, on the owner's explicit request (2026-10-12), after a `pg_dump` in `/opt/lazycake/backups/`; the plan was to wipe the database afterwards. Fake machines are marked connected but have no agent: a coordinator restart marks them offline, and so does any queued task (the scheduler tries to dispatch to them, fails and flips them) |
| `web/e2e/seed.py` | realistic demo data for a **demo** database (destructive) | never run against production |
| `deploy/chaos-demo.sh`, `deploy/docker-compose.yml` | local demo/compose stack (Postgres, migrate, coordinator, agents) | compose uses the weak demo DB password; dev only |
| `testdata/netns-spike.sh` | manual spike for the netns proxy | historical |

The built-in images: `deploy/Dockerfile` has stages `coordinator`, `agent` (agent + `lcinit` next to it, which the agent discovers), `gateway`, `lcctl`, `refworkload` and `lcbench`; each `go build` there stamps `internal/version.Version` from `--build-arg VERSION`.
